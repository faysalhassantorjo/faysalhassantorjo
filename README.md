### 🎥 Video Processing Platform

A video upload and processing application using asynchronous workers.

The project explores how a backend can delegate expensive video-processing tasks to separate workers instead of blocking the main web server.

**Architecture includes:**

```text
Client
   │
   ▼
Django API
   │
   ▼
Message Broker
   │
   ▼
Celery Worker
   │
   ▼
FFmpeg
   │
   ▼
Processed Video
```

**Tech:** `Django` `Celery` `RabbitMQ` `Docker` `FFmpeg`

### 📊 High-Scale View Counting

I've also been exploring how large platforms can handle huge numbers of post views without writing every single view event directly to the main database.

I'm experimenting with concepts such as:

* Redis
* Counters
* HyperLogLog
* Asynchronous processing
* Event-driven architecture
* Periodic database aggregation

The goal is to understand how systems can handle **high write throughput while keeping the primary database healthy**.

## 🏗️ My Engineering Philosophy

> **Don't just learn how to use a technology. Learn why it exists.**

When learning a technology, I try to understand:

```text
Problem
   ↓
Why does this technology exist?
   ↓
How does it solve the problem?
   ↓
What happens internally?
   ↓
What happens when the system scales?
   ↓
What are the trade-offs?
```

That's why I'm particularly interested in **system design and distributed systems**.
